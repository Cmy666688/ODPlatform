# WSODD 精度提升实验（2026-10-27）

基线任务 `c6e42c0be10949318a22cc23d3bcbf1a` 的独立测试 mAP50 为 16.9179%、mAP50–95 为 8.1831%。
本轮任务 `a96af53dc51d4231820eac5350f7ab3e`，配置保存于 `apps/platform/configs/runtime/wsodd_accuracy.yaml`。
运行状态、曲线与最终指标以 `runs/web_jobs/<任务 ID>/` 为准；本文件不预先承诺精度。

## 基线诊断

- 验证 mAP50–95 最佳在第 11 轮（9.147%），此后训练损失下降而验证表现没有同步提升。
- 训练集共 13756 个框；按原图宽高等比缩放计算，约 54.24% 的框在长边缩放至 640 后，框短边不足 16 像素。
- 类别存在长尾及分组差异：训练 mast 33 个、验证 281 个；训练 tree 138 个、验证缺类。沿用原划分并保留这些限制。
- 图片推理中的船舶漏检和岸桥区域大框说明需要同时关注召回与定位，降低显示阈值不能替代模型改进。

使用验证集 fitness 选择 best，再进行独立测试；报告所有类别与 P/R/mAP，不以降低阈值或改变划分抬高指标。
原 test 已用于基线评估，本轮是既有测试集复测，仍需新的外部场景才能验收更广泛泛化能力。

## 数据副本修正

基线训练日志记录了引擎自动重新保存部分 JPEG 的行为。为防止训练改写冻结文件，新流程在任务目录生成独立的
`engine_dataset/`，复制标签并隔离缓存；对可解码、但最后两字节不是 JPEG EOI 的文件，仅在副本补结束标记，不重压缩像素。
`engine_dataset_audit.json` 保存原件与派生文件 SHA256。单元测试验证原件/像素/标签不变以及缓存隔离。

本轮复用远端已传输的完整原数据包恢复冻结字节，启动前再次逐文件核验，避免重新上传 1.8GB。
没有复制 train 样本到 val/test，也没有合并为二分类。

boat AP50 从 17.76% 提升至 35.71%，ship AP50 从 31.97% 提升至 34.87%。

无测试样本类别保留空值，不填充平均数。模型由验证 fitness 选出的第 26 轮 best，未使用 test 选 checkpoint。

原港区漏检图片复核任务 `2926757f5274401c90cb694e38d1982d` 已完成，继承新权重与 960 输入，显示阈值仍为 0.25。

照片没有人工 GT，该结论是定性复核，不能折算为精度指标。岸桥区域原有大框有所减少，仍存在其它误报。

## 耗时复核

## 4090 快速训练实测

参考 [ShipYOLO 的 WSODD 项目](https://github.com/Bilallbayrakdar/ShipYOLO) 使用 512 输入，
及 [水面目标 YOLOv5 项目](https://github.com/rTiagoS/water-surface-object-detection) 使用 416 输入、batch 16 和缓存。
两者的数据划分、模型及实验条件不同，不能直接比较其精度或推导 4090 的训练耗时。

吞吐测试使用完整的 5638 张训练图。s/960、batch 32、8 workers、RAM 缓存的第二轮训练约 29.09 秒，含验证约 33.30 秒；
s/640、batch 64、矩形训练的第二轮训练约 10.48 秒，含验证约 14.36 秒。探针只跑两轮，不代表最终精度。

快速实验 `47d3650382b947739b91e785cefbc13b` 采用官方 COCO 预训练 YOLOv8s、640、batch 64、30 轮、
workers 8、RAM 缓存、矩形训练、AMP、关闭严格确定性；完整训练图、14 类、原分组和测试集均保留。
远端从工作进程开始到训练、独立测试和 48 张图生成共 **535.90 秒（8 分 56 秒）**；
其中训练与逐轮验证的 results.csv 最终时间为 **444.75 秒（7 分 25 秒）**。
数据上传、远程启动前的质检及网络回传不计入该计算时间，不能保证全部端到端步骤都在十分钟内。
此次远端计算完成于 10:44:17（北京时间），全部产物本机回传完成于 11:00:42，回传约 16 分 25 秒；
传输速度受网络影响，并非 GPU 仍在训练。48 张对比图与权重均已归档。

| 777 张测试图 | 原 n/640/50 | 精度方案 s/960/60 | 快速方案 s/640/30 |
| --- | ---: | ---: | ---: |
| mAP50 | 16.92% | 23.76% | 11.67% |
| mAP50–95 | 8.18% | 10.33% | 4.74% |
| Precision | 47.93% | 51.96% | 38.25% |
| Recall | 21.82% | 28.19% | 12.50% |

快速方案牺牲精度，适合速度和流程验证；精度方案的最佳权重继续保留用于需要更好检测效果的场景。
矩形训练关闭 mosaic、关闭严格确定性会改变训练方式；上述多项同时调整，不能仅凭本次对照断言单个因素造成精度下降。
相同数据身份的远端数据经核验通过后可复用，避免每次重新上传原包；启动时仍进行全量身份与质检检查。

## 从最佳权重继续微调

在 `a96af53dc51d4231820eac5350f7ab3e` 的最佳权重基础上开始新的 10 轮微调，优化器重新初始化，
并非从上次 last 检查点恢复优化器状态。数据指纹和 5638 / 1052 / 777 划分不变，输入 960、batch 32、8 workers、
RAM 缓存、AdamW 初始学习率 0.0001、余弦衰减、mosaic 0.5，后 3 轮关闭 mosaic；AMP 开启、严格确定性关闭、seed 42。
使用完整验证集比较原权重和新 best，以 `0.1*mAP50+0.9*mAP50–95` 为选择标准，再运行原测试集，测试不参与选模。

验证集 mAP50 从 21.96% 提升至 22.70%，mAP50–95 从 11.28% 提升至 12.39%。
原模型和候选模型使用同样的 960 输入、batch 32、IoU 0.7、置信度下限 0.001 在 777 张测试图复测：

| 测试指标 | 微调前 | 微调后 | 变化（百分点） |
| --- | ---: | ---: | ---: |
| mAP50 | 23.76% | 24.88% | +1.12 |
| mAP50–95 | 10.33% | 11.52% | +1.19 |
| Precision | 51.96% | 54.08% | +2.12 |
| Recall | 28.19% | 29.04% | +0.85 |

训练与测试计算阶段用时 469.01 秒（7 分 49 秒），不含提前准备数据、额外可视化和网络传输。
其中训练及逐轮验证用时 383.27 秒（6 分 23 秒），验证 fitness 最佳为微调第 7 轮。
boat AP50 从 35.71% 到 41.30%，ship AP50 从 34.87% 到 36.12%；person AP50 从 1.79% 降到 0.29%，mast 仍为 0。
指标不是所有类别均改善，原 test 已被多次复测，因此仍需新的外部场景评估泛化。
